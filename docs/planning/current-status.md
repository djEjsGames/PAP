# PAP 현재 기획·구현 상태

갱신일: 2026-10-31 (Asia/Seoul)

개발 세션 **Create Godot PAP project** (`01a164d7-0aeb-7162-aeba-a72d3e0f4b5b`)의 사용자 직접 요청, 완료 보고와 관련 검토 문서를 확인해 정리했다. 이전 검증 수치는 개발 세션의 보고이며, 10월31일 별도 기획 교차검증은 마지막 항목에 구분해 기록했다.

## 역할과 기획 기준

- 이름은 **Paper Airplane Park**, 약칭 **PAP**.
- 최신 확정 변경은 기본 발사 높이 지면 위1.7m와 용지4종(색종이15×15cm/80g/m², A4복사용지21×29.7cm/80g/m², 신문지39.1×54.5cm/45g/m², 4절도화지39.4×54.5cm/120g/m²)이다. [용지와 선택 UX](paper-options-2026-10-26.md)를 개발 요청 기준으로 사용한다. 기존 도면·기록을 소급 변경하지 않는다. 네 용지 선택·물성·저장 호환과 새 1.7m 발사를 구현·검증했다. [구현 결과와 검토 화면](../reviews/paper-stock-implementation-2026-10-26.md)을 보고 사용자 체감을 확인할 단계다.
- 이 세션은 기획·검토를 담당하고, 구현과 실행 검증은 개발 세션에서 수행한다.
- 개발 세션에서 사용자가 직접 확정한 후속 요구를 이전 기획 제안보다 우선한다.
- 핵심 재미는 직접 접은 비행기를 공원에서 날리고 비행을 지켜보는 것이다. 정상 비행 최소 3초는 확정 조건에서 제외하고 재검토 중이다.
- 최신 전체 흐름은 배회 공간 시작 → 발견물/쓰레기 → 지정 작업대 접기 → 실물 기체 인벤토리 → 원하는 위치에서 시선 방향 투척 → 관람·회수다. [공원 중심 개발 순서](park-core-loop-2026-10-26.md)를 다음 작업 기준으로 삼는다. 첫 구현은 고정 기체로 이동부터 회수까지 연결하고, 랜덤 모형·정식 공원·봉사 보상은 후속이다.
- 공원 활동·대회·NPC 비행기 참고·훈련과 성장·경제는 기획 방향이며, 아래 구현 완료 목록과 구분한다.

## 구현 완료 보고를 확인한 항목

### 접기·저장·종이층 표현

- 날개 1·2와 손잡이 지정, 미리보기·확정, 실제 펼침과 프리셋 반영.
- 기본 준비 자세는 손잡이 아래, 양 날개 기본 벌림 90°.
- 종이 도면 프리셋 저장·불러오기, 종이 형상·접기 이력·기준점/선 복원. 기존 저장 경로와 데이터 호환 유지.
- 겹친 종이층의 표시 순서가 펼치는 방향을 따르도록 수정. 종이 양면 색과 경계선 유지. 물리 정점·법선은 바꾸지 않은 표시 수정이다.

### 발사 게이지: 사용자 직접 요청으로 확정된 최신 방식

- 준비 중 **↑/↓**로 목표 고도각을 직접 설정한다.
- Enter/Space 또는 버튼으로 강도 게이지를 시작하고, 다음 입력으로 강도를 확정한다.
- 올라가는 중에 강도를 정해도 커서는 끝점까지 진행한 뒤 원점으로 돌아온다. 이미 돌아오는 중이면 그대로 복귀한다.
- 마지막 원점 입력의 오차는 **고도각에만** 적용한다. 좌우 방향이나 강도, 기체 자세에는 타이밍 편차를 주지 않는다.
- 원점 판정 영역은 전체 **20px(좌우 10px)**. 영역 안은 편차 0, 밖은 경계를 벗어난 정도에 비례한 편차다.
- 일찍 입력하면 위쪽, 늦게 입력하면 아래쪽 편차가 발생한다. 끝까지 입력하지 않으면 빗맞은 상태로 자동 발사한다.
- 목표·실제 고도각, 편차, 타이밍과 자동 빗맞음을 결과·덤프에 기록한다.
- 이 방식은 기획 세션의 이전 '힘 확정 후 고도각을 별도 게이지로 직접 선택, 타이밍 편차 없음' 제안을 대체한다.

### 비행 UI·카메라

- 자세 조정은 접을 수 있는 영역, 결과는 오른쪽 팝업으로 분리했다.
- 발사 좌우 방향 UI는 제거하고 정면 0° 고정을 유지한다.
- **일반 드래그로 기체 자세를 변경하지 않는다.** 자세 변경은 축별 회전 링과 수치 입력으로 한다.
- **우클릭 드래그는 카메라 회전, 휠은 확대·축소**다. 준비 중·비행 중 모두 사용할 수 있고 재시도에서도 시점을 유지한다.

### 바람

- 오른쪽 아래 HUD를 초기 크기의 약 1.5배로 확대했다.
- 랜덤은 수평 방향과 **0.5–3.0m/s**, 리셋은 무풍이다. 바람은 실제 공력·HUD·결과·덤프에 연결돼 있다.
- 바람은 한 비행 동안 일정하며 게이지 진행·비행 중에는 변경하지 않는다. 재시도 시 유지한다.
- 화살표는 현재 카메라 기준 X/Y/Z 성분으로 입체 방향을 표시한다. 랜덤 바람에 수직 성분을 추가했다는 뜻은 아니다.
- 화살표는 두께를 기존 입체 모델의 18%로 줄인 납작한 형태이며, 길이축 자체 회전 속도가 풍속에 비례한다.

### 과회전·에너지 폭주

- 문제 덤프의 240Hz 에너지 증가와 엔진 회전 상한 도달을 재현했다.
- 압력중심의 국소 속도로 공력을 계산하고 같은 위치에 적용하도록 수정했다.
- 회전 양력에 면 중심 기준 토크를 반영하고 순수 회전에서 앞뒷면 방향에 따라 힘이 달라지는 문제도 수정했다.
- 강한 감쇠나 새 회전 상한으로 증상을 가리는 방식은 사용하지 않았다.
- 문제 덤프는 수정 후 240Hz에서 약 **1.45초에 착지**했다. 비대칭 날개·바람·240/480/960Hz를 조합한 18개 비행에서 에너지 폭주와 회전 상한 도달이 없었다.
- **시간 간격에 따른 궤적 수렴은 아직 미해결**이다. 문제 덤프 착지 시간은 240/480/960Hz에서 약 1.454/2.067/1.405초로 달랐다. 폭주 수정 완료를 전체 비행 정확도 검증 완료로 해석하지 않는다.

## 검증·배포 상태와 남은 검토

- 최신 카메라 변경의 GPU 검사 보고는 **13,477개, 실패 0건**이다.
- 공력 수정은 별도 에너지 검사 10,120개와 기존 평판 검사 36개를 통과했고 자동 검사에도 연결됐다.
- GitHub Pages 웹 테스트 환경은 이미 구축돼 있다. 다만 이후 최신 공력·바람 표현·카메라 변경은 완료 보고상 웹 재빌드·배포되지 않았다. 공개 사이트와 로컬 최신 상태를 같다고 간주하지 않는다.
- 게이지 속도, 20px 원점 판정과 편차 크기, 수정 후 비행 느낌은 사용자 플레이 검토가 필요하다.
- 물리 후속 과제는 시간 간격별 궤적 수렴 확인이다. 하위 스텝·적분 개선·전체 관성 텐서는 아직 적용 완료로 기록하지 않는다.
- Safari·실제 태블릿 터치의 검증 완료 보고는 없다.
