# 표적 비행 개선본 — 구현·플레이 검증 기준

2026-10-31. 사용자가 개발 세션과 논의하여 직접 검증할 개선본을 준비하도록 요청했다. [이전 재미 검토](../reviews/fun-review-2026-10-31.md)의 제안 중 아래 범위를 구현한다. 제품 코드는 개발 세션, 계획과 별도 교차검증은 기획 세션에서 담당한다.

## 이번에 확인할 경험

**한 번 던져보고 → 어디가 달라졌는지 보고 → 한 가지를 바꿔 → 한 번 더 던지고 싶어지는가.**

실물 기체 한 대와 표적 하나로 5분 정도 플레이한다. 자유 비행·배회는 유지하며 표적 참여는 선택이다. 성공을 강제하기 위해 중력·용지·비행 높이·기체 형상·게이지 규칙을 바꾸지 않는다.

## 개발 범위와 합의 기준

| 항목 | 검증본의 동작 |
|---|---|
| 선택적 연습 구역 | 안전한 발사선과 약4m 앞, 반지름 약1m인 표적을 표시한다. 목표가 실제 조준 방향에 있고, 어디서 참여하는지 알아볼 수 있어야 한다. 수치는 플레이 검증용 초기값이다. |
| 첫 착지 판정 | 실제 첫 지면 접촉과 최종 정지를 구분한다. 표적 안/밖과 중심 오차를 표시한다. 굴러 들어온 결과를 첫 착지 성공으로 바꾸지 않는다. |
| 판정의 맥락 | 발사 시의 연습 여부·표적 중심/반지름을 보존한다. 발사선을 벗어난 자유투척, 취소, 막힌 발사, 수치 오류와 정상 연습 결과를 섞지 않는다. 첫 접촉을 확인하지 못하면 판정 불가로 표시한다. |
| 최근3회와 직전 궤적 | 같은 실물을 회수해 재준비해도 기록을 비교할 수 있다. 힘·목표각·날개 등 바뀐 변수를 짧게 강조한다. 기체/용지/바람 변경은 비교 전제의 차이를 알린다. |
| 회수 후 재투척 | 내 기체는 가까이 가서 회수하면 같은ID로 바로 손에 든다. 다른 기체를 들고 있었다면 기존 기체는 안전하게 보관한다. 보관함은 계속 선택 가능하다. 새 발견물의 관찰·처리 선택은 유지한다. |
| 관찰 화면 | 비행 중에는 큰 투척 제어판을 작은 관람 정보로 줄인다. 기체·표적·직전 궤적을 읽을 수 있어야 하고, 결과/복귀/바람은 유지한다. |
| 시작 준비 | 기본 색종이와 기존 공원 발견 기체를 유지한다. 발견 기체를 보관해 테스트하거나 본인 기체를 쓸 수 있게 안내한다. 자동 실물 복제나 순간 회수는 추가하지 않는다. |

기존3입력 게이지와20px 원점, 고도각 편차, 오디오 성공/실패 구분을 유지한다. 여러 코스·NPC·경제·랜덤 발견·전체 영구 저장은 이번 범위가 아니다. 실속 등 원인이 검증되지 않은 비행 조언도 만들지 않는다.

## 사용자 플레이 순서

상점 추가 후 새 공원은100코인·빈 보관함으로 시작한다. 아래 기존 발견 비행기로 연습하거나, [상점에서 종이를 구매해 접는 순서](paper-shop-playtest-2026-10-31.md)를 사용한다. 인벤토리 키는 사용자 후속 요청으로 **Tab**이다.

1. `D:\Works\Git\PAP\project.godot`을 열고 **F5로 공원부터 새로 실행**한다. 이미 실행 중이던 게임은 종료 후 다시 시작한다.
2. 바닥의 ‘공원에서 발견한 비행기’ 바로 옆으로 걸어가 **E → 살펴보기 → 보관하기**를 선택한다. 상점에서 산 종이를 직접 접은 기체를 사용해도 된다.
3. **Tab → ‘공원에서 발견한 비행기’ 선택 → ‘꺼내기 · 손에 들기’**를 누른다.
4. 작업대 오른쪽의 밝은 **시작선 중앙 근처**로 걸어가 **T**로 표적 연습에 참여한다. 원은 정면4m 앞, 반지름1m다. 참여 시 플레이어나 기체가 순간 이동하지 않는다.
5. **Space로 준비**, 고도각10°·힘 약60%·양 날개90°·무풍을 첫 참고값으로 사용한다. 기존 방식대로 Space/Enter로 게이지를 시작하고 힘을 고른 뒤 돌아오는 원점에서 던진다. 수동 입력이므로 정확히60%일 필요는 없다.
6. 첫 착지의 표적 안/밖과 중심 오차를 본다. 첫 접촉점의 초록 ○는 표적 안, 주홍 X는 표적 밖, 하늘색 +는 자유 투척이다. 표식은 굴러가는 기체를 따라가지 않는다. 결과창에서 첫 지면 접촉과 이후 정지확정 거리가 따로 표시되는지 확인한다.
7. **B로 공원 복귀 → 기체 옆으로 걸어가 E로 회수**한다. 같은 기체가 바로 손에 들어온다. 시작선으로 걸어 돌아가 표적 방향으로 조준하고 **Space**로 다시 준비한다. Tab으로 다시 꺼낼 필요는 없다.
8. 2회차는 가능한 한 비슷한 투척에서 **고도각 또는 날개 벌림 한 가지**를 바꿔본다. 예: ‘자세/날개’에서 양 날개 벌림을90°→110°로 바꾸기. 게이지로 힘도 달라질 수 있으므로 결과의 ‘바꾼 조건’을 함께 본다. 주황색은 직전 비행 궤적이다.
9. 3회차는 본인 판단으로 다시 조절한다. 최근3회 비교가 이어지고, 다음에 더 잘 맞히고 싶은 마음이 생겼는지 적는다.
10. 공원으로 돌아온 뒤 **T**로 연습을 나가 일반 투척과 발견물 관찰도 한 번 확인한다. 시작선 밖에서의 투척은 연습 판정과 구분된다.

## 구현·교차검증 완료 조건

- 실제 엔진 접촉으로 표적 안/밖을 판정하고, 첫 접촉 후 굴러 들어온 경우도 확인한다.
- 같은 기체로3회 실투척 후 최근 기록3개와 직전 궤적, 회수·재준비의 ID/수량 보존을 확인한다.
- 기체/용지/바람 변경, 취소/막힌 발사, 다중 접촉, 결과 모달/Esc, 오디오 중복을 확인한다.
- 1280×720/640×360에서 시작 안내·연습·비행·착지·최근 기록 화면을 GPU로 검토한다.
- 기존 자유 투척·접기·발견물 선택이 유지돼야 한다.
- 실행 방법·최종 조작·화면·검사 결과·미확인 범위를 정리해 사용자가 로컬에서 검증할 수 있게 한다. 배포·커밋·푸시는 요청하지 않았다.

## 기획 세션 교차검증 결과

`build/practice_cross_review_20261031.gd`로 새 공원의 기존 발견물을 실제 엔진 입력으로 확보하고, 시작선까지 걷고, T 참여와 실제 게이지 투척3회를 진행했다. 매회 걸어서 회수·시작선 복귀를 했으며 플레이어 위치나 종이를 순간 이동·복제하지 않았다. GPU46검사가 통과했다.

| 회차 | 실제 힘 | 첫 접촉 중심 오차 | 첫 접촉 판정 | 기록 수 |
|---|---:|---:|---|---:|
| 1 | 61% | 0.691m | 안 | 1 |
| 2 | 81% | 3.004m | 밖 | 2 |
| 3 | 41% | 1.007m | 밖 | 3 |

각 회차는 무풍·고도각10°·날개90°였다. 세 번째는 실제 첫 접촉 후 정지확정 위치가 중심 오차 약0.951m로 원 안에 들어갔지만, 첫 접촉 기준의 ‘밖’ 판정을 유지했다. 이는 위치를 강제로 바꾼 사례가 아니다. 같은 발견 기체ID2와 전체 실물2개, 회수 즉시 손 소유, 이전 궤적과 최근3회 복원을 확인했다.

이 과정의 시작/준비/관람/3회 결과/회수 화면은 `build/practice_cross_review_20261031/`에 보존했다. 3D 안내가 근거리에서 지나치게 커 보이는 점과, 종이의 최종 위치가 아닌 첫 접촉 지점을 시각적으로 표시할 필요를 개발 세션에 전달했다.

후속 GPU 화면에서 짧아진 안내, 결과창의 표식 범례·첫 접촉/정지 구분, 회수 후 ‘시작선으로 걸어가 Space’ 안내를 확인했다. 시각 보완 뒤 실제 입력 1회 왕복도 14검사/실패0건이었다. 이 추가 검사는 전체 3회 검사를 대체하지 않는다.

현재 상태: **로컬 개선본 준비 완료, 사용자 플레이 평가 대기.** 개발 완료 보고와 연습 GPU·헤드리스 각148검사/실패0건, 기존 회귀 통과 로그를 확인했다. 마지막 표식 높이 보완은 별도 GPU1검사와 실제 PNG로 확인했다. 접촉 좌표·판정은 유지하고 표시 높이만 바닥 원 위로 둔다. 전체 연습148검사는 이 마지막 표시 높이 보완 전 결과다.

[개발 구현·검사·화면 기록](../reviews/target-practice-implementation-2026-10-31.md)을 함께 참고한다. 위 사용자 체크박스는 직접 플레이 전 상태다. 엔진 자동 입력 검사는 사람의 손 조작·재미 평가를 대신하지 않는다. 기록은 현재 실행 세션에 남으며 새 게임 실행 시 초기화된다. 이번 변경은 로컬에만 적용했고 웹 배포는 하지 않았다.
