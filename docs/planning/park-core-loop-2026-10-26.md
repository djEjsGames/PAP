# 공원 중심 게임 흐름과 개발 순서 — 2026-10-26

## 사용자 확정 방향

1. 처음부터 배회 가능한 공간에서 시작한다.
2. 공간에는 랜덤한 쓰레기·발견물이 놓인다.
3. 특정 지역의 작업대에서 종이접기를 한다.
4. 접은 종이비행기는 인벤토리에 보관한다.
5. 원하는 위치에서 바라보는 방향으로 던진다.

기획 보완은 던진 비행기의 회수까지 이어서 탐색 → 발견/수거 → 작업대 접기 → 보관 → 투척 → 관람 → 회수/새 발견의 한 흐름으로 만드는 것이다. 발견물을 쓰레기 또는 활용할 재원으로 판단하는 것은 플레이어에게 맡긴다.

이 문서는 기획 세션의 작업 순서 전달용이다. 제품 구현·실행 검증은 개발 세션에서 담당한다.

## 이번 첫 구현 범위

**아래 1–5단계의 최소 루프를 실제로 완주하는 검토본**을 만든다. 정식 공원 미술, 복잡한 캐릭터, 랜덤 생성 전체, 봉사 보상·경제는 이후 범위다. 단계별로 확인하되 중간 기능만 나열하고 끝내지 않는다.

| 순서 | 작업 | 단계 완료 기준 |
|---|---|---|
| 1 | 배회 가능한 임시 공간과 플레이어 | 시작 직후 이동·시점 조절이 되고 가까운 작업대를 발견할 수 있음 |
| 2 | 작업대에서 기존 접기 기능 사용 | 접근·상호작용으로 접기 진입, 종료 후 원래 위치·시점으로 복귀 |
| 3 | 완성 기체 보관·선택 | 접기를 마치고 실물 기체를 보관한 뒤 꺼낼 수 있음 |
| 4 | 공간 안에서 조준·게이지 투척 | 작업대 밖 원하는 위치·방향에서 실제 물리 기체를 던질 수 있음 |
| 5 | 추적 관람·착지·회수 | 관람 종료 후 플레이어로 복귀하고 같은 기체를 주워 다시 사용할 수 있음 |
| 후속 6 | 랜덤 모형과 발견물 배치 | 기본 모형의 유효한 변주를 공간에서 발견·수거·관찰·활용 |
| 후속 7 | 공원 구성과 봉사활동 | 확인된 발견 거리·배치 밀도·회수 동선을 바탕으로 공원·수거 보수 구성 |

## 1. 이동과 발견

- 최소 공간은 충돌이 있는 바닥, 단순 플레이어 표시, 작업대 하나, 날릴 여유 공간으로 구성한다. 작업대와 시험 공간은 가깝게 둔다.
- 처음부터 캐릭터 외형·애니메이션·정식 공원 자산을 요구하지 않는다. 테스트용 시점은 캐릭터 위치와 이동을 파악할 수 있는 간단한 3인칭을 우선한다.
- WASD 이동, 우클릭 드래그 시점 회전, 휠 확대/축소를 기본으로 한다. 기존 카메라 조작과 일관되게 연결한다.
- 근처의 상호작용 가능한 대상 하나를 강조하고 대상 근처에 이름/행동/키를 표시한다. 키는 E를 기본 상호작용으로 사용해도 좋다. 반복 안내창을 띄우지 않는다.
- 고정 비행기 한 개나 개발용 배치물로 접근·대상 인지를 확인한다. 이 단계에서 무작위 생성이 선행될 필요는 없다.

## 2. 작업대와 접기

- 플레이 시작 시 기본 색종이 한 장을 제공해 봉사활동을 먼저 해야만 핵심 접기를 할 수 있는 구조로 만들지 않는다.
- 작업대에 접근해서 기존 접기 편집기에 들어간다. 접기 중에는 이동 입력과 세계 상호작용을 받지 않고, 종료하면 원래 플레이어 위치·카메라 맥락으로 돌아온다.
- 기존 접기 방식, 부위 지정, 내 도면 저장/불러오기, 용지 선택, 스냅을 재사용한다. 종이접기 자체를 새로 구현하지 않는다.
- 결과를 인벤토리에 넣는 명시적 행동은 **접기 마치고 보관**처럼 결과를 설명한다. 모든 모양을 비행기 완성 판정으로 제한하지 않고 연결이 보존된 자유 접기를 유지한다.
- 기존 인벤토리 기체를 작업대에서 수정할 때는 같은 기체를 갱신한다. 완료 버튼 중복 입력으로 복제되지 않게 한다. 단순 관찰이나 취소가 원본을 덮어쓰면 안 된다.

## 3. 인벤토리의 의미

- **실물 기체**와 **도면(접는 방법)**을 구분한다. 도면 저장은 기존 기능이고, 도면을 저장했다는 이유로 실물 기체가 여러 개 생기지 않는다.
- 첫 UI는 작은 목록/카드로 충분하다. 기체 미리보기·이름·용지 종류·실제 크기를 보여 주고 꺼내기/작업대에서 수정하기를 연결한다. 무게 제한·희귀도·장비 슬롯 확장 같은 부가 규칙은 추가하지 않는다.
- 기체에는 종이 형상·재료 좌표·접기 이력·용지 물성·부위 지정·날개 설정 등 재현에 필요한 상태를 보존한다.
- 같은 실물은 보관 중/작업 중/손에 든 상태/비행 중/바닥에 놓인 상태 중 하나에만 존재한다. 던지면 보유 수량에서 빠지고 세계에 존재하며, 회수하면 같은 기체가 돌아온다.
- 첫 검토본의 인벤토리·바닥 기체·비행 기록은 실행 중 세션 범위로 둔다. 기존 도면 프리셋의 영구 저장은 유지한다. 전체 공원/인벤토리의 종료 후 복원은 후속 저장 기획으로 남긴다.
- 이번 단계에서 용지 가격·소모 경제·봉사활동 보상을 도입하지 않는다. 테스트용 기본 용지를 사용할 수 있게 둔다.

## 4. 시선 방향 투척

- 주 게임 흐름에서 투척을 위해 별도 시험 공간으로 이동시키지 않는다. 플레이어가 서 있는 세계의 위치에서 던진다. 기존 독립 시험 기능은 개발 회귀 검증용으로 보존해도 된다.
- 발사 위치는 **플레이어가 딛는 지면 기준 1.7m의 기체 무게중심**이다. 세계의 고정 좌표 `(0,1.7,0)`에서 발사하지 않는다.
- 비행기를 꺼내 현재 바라보는 좌우·상하 방향을 목표 방향으로 사용한다. 별도 좌우 슬라이더를 만들지 않는다. 기존 '정면 고정'은 플레이어/조준의 정면 기준으로 바뀐다.
- 월드 투척의 목표 고도각은 시선에서 읽는다. 기존 독립 시험의 상하키 목표값과 세계 조준값이 서로 경쟁하지 않게 한다. 기존 원점 오차는 여전히 고도각에만 적용한다.
- 게이지 시작 시 위치/조준 방향/목표 고도각을 확정하고 이동과 조준 변경을 잠근다. 실제 발사 또는 취소에서 상태를 명확하게 전환한다. 취소는 인벤토리 기체를 소비하지 않는다.
- 강도 확정 후 끝점 진행·원점 복귀·20px 영역·고도각 편차·자동 빗맞음 규칙을 유지한다. 실제 발사값과 목표값을 기록한다. 기존 수동 기체 자세 보정은 조준 방향과 충돌하지 않도록 유지한다.
- 벤치·벽 등 바로 앞 물체와의 충돌을 무시하고 뚫고 나오게 하지 않는다. 공간 안의 유효한 위치에서 자유 투척이 된다는 뜻으로 구현한다.

## 5. 비행 관람과 회수

- 발사 시 기체를 따라가는 기존 관람을 이어 간다. 플레이어는 발사 지점에 남으며, 관람 종료 후 그 플레이어 시점으로 복귀한다. 시점 복귀와 비행 종료를 구분한다.
- 실제 기체는 세계의 같은 위치에서 계속 존재한다. 기존 시험의 시간 제한이 세계 기체를 삭제하거나 공중에 고정하는 결과가 되지 않게 한다.
- 착지한 비행기는 접근·회수할 수 있고 실제 접기/물성/부위 상태가 유지된다. 간단한 착지 위치 표식이나 근거리 강조로 찾기 쉽게 한다.
- 물건이 인벤토리와 세계에 중복되거나 회수 때 다른 도면으로 바뀌지 않아야 한다. 회수한 비행기를 살펴봐도 별도의 내가 접던 기체를 덮어쓰지 않는다.
- 첫 검토는 하나의 기체로 이동 → 작업대 → 보관 → 투척 → 착지 → 회수 → 다시 투척까지 수행한다. 결과·바람·카메라·부위 확인의 기존 입력 분리를 보존한다.

## 후속 6–7의 방향: 이번에는 순서와 연결점만 확보

- 기본 모형 네 종류를 실제 접기 이력이 있는 모형으로 만든 다음 지원되는 용지·색·허용 오차·날개 벌림 안에서 변주한다. 종이 연결을 깨는 무작위 메시는 사용하지 않는다.
- 처음에는 고정 발견물로 회수/관찰/재사용을 확인하고, 이후 랜덤 배치·생성으로 전환한다. 같은 물건이 자동으로 희귀/좋음/쓰레기 등급을 받지 않는다.
- 회수·살펴보기·그대로 날리기·도면 참고·정리를 플레이어가 선택한다. 수거 보상과 발견물 활용은 함께 가능하게 한다.
- 실제 공원 장식과 동선·발견 밀도·봉사활동 보수는 첫 루프 플레이 결과를 보고 구체화한다. NPC 행동·상점·대회·구김/오염은 이번 최소 구현에 추가하지 않는다.

## 현재 구현에서 보존할 사항

- 개발 세션의 최신 사용자 직접 요청을 우선한다. 용지는 색종이15×15cm/80g/m², A4복사용지21×29.7cm/80g/m², 신문지39.1×54.5cm/45g/m², 4절도화지39.4×54.5cm/120g/m²다. 신문지·도화지를 이전 제안인15cm로 되돌리지 않는다.
- 선 긋기15° 스냅과 Shift 해제, 기존 우선 스냅, 도면 호환, 층 표시, 공력 작용점 수정, 용지별 질량·관성, 우클릭/휠 카메라 조작을 유지한다.
- 옛 도면·덤프의 실제 치수·평량·발사 기록을 소급 변경하지 않는다.
- 인벤토리 조작·작업대·회수·게이지·결과창 입력이 서로 새지 않게 한다. UI 위 클릭/키 홀드/Esc/취소로 중복 보관·발사·회수가 발생하지 않아야 한다.

## 검토 결과물

- 1–5단계가 이어지는 실행 가능한 검토본과 연속 화면을 제출한다. 각 단계의 완료 여부와 남은 항목을 구분한다.
- 이동 시작/작업대 상호작용/접기 마치고 보관/인벤토리 선택/서로 다른 위치·좌우·상하 조준의 발사/추적 종료/착지 회수/재투척을 확인한다.
- 기체 단일 소유 상태, 물성/접기 보존, 취소·중복 입력, 기존 도면 호환과 주요 회귀를 검증한다.1280×720와640×360에서 대상 안내와 주 행동이 가려지지 않는지 확인한다.
- 기존 웹 테스트 환경에서도 이동 키·우클릭·휠·UI 포커스·저장 도면을 가능한 범위에서 확인한다. 별도 공개 배포는 이번 요청 범위가 아니다.
- 전체 공원 미술이나 랜덤 생성 완성 여부를 첫 검토본의 통과 조건으로 삼지 않는다. 사용자 플레이에서 이동·접기·회수 동선이 자연스러운지는 검토본으로 확인한다.
