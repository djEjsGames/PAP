# 시작 직후 색종이를 손에 들 때 발생하는 오류

검토일: 2026-10-28. 사용자 실행 로그와 동일한 실패를 현재 코드에서 재현했다. 제품 코드와 사용자 저장 데이터는 변경하지 않았다. 개발 세션에 최소 수정과 초기 상태 회귀를 요청했다.

## 원인

`park.gd`의 `_ready()`는 초기 색종이를 `faces=Paper.square()`, `history=[]`로 만든다. `faces`는 타입이 지정된 `Array[Dictionary]`지만, 딕셔너리 안에 바로 넣은 빈 `history`는 타입이 없는 `Array`다.

시작 → I → ‘꺼내기 · 손에 들기’를 누르면 소유 상태를 손으로 바꾼 다음 `_update_character()`가 손에 들 종이의 표시를 생성한다. 이때 `Parts.valid(..., data.sheet.history)`는 `Array[Dictionary]` 인수를 요구하여 호출 단계에서 중단된다. 빈 비행 부위 데이터여서 함수 안에서 false를 반환할 수 있는 경우에도, 함수 본문에 들어가기 전 타입 검사에서 실패한다.

이는 종이 형상·층 간섭 판정 실패와 다른 초기화 결함이다. 종이를 먼저 접거나 저장할 필요가 없어야 하므로, UI에서 해당 행동을 막는 방식으로 처리하지 않는다.

## 재현 근거

사용자 최신 `godot.log`에서 확인한 오류:

```text
SCRIPT ERROR: Invalid type in function 'valid' in base 'GDScript'.
The array of argument 3 (Array) does not have the same element type
as the expected typed array argument.
at: _update_character (res://scripts/park.gd:301)
```

새 공원 인스턴스에서 보관함을 열고 실제 꺼내기 버튼 신호로 재현했다. 그 전에는 편집·저장·도면 로드를 하지 않았다.

| 확인 | 원본 초기 상태 | 진단 중 메모리에서 빈 이력 타입만 지정 |
|---|---|---|
| 초기 history.is_typed() | false | 변경 전 false → 변경 후 true |
| 소유 상태 | held_id=1 / hand | held_id=1 / hand |
| 손 표시 캐시 carried_id | -1 | 1 |
| 손 표시 mesh | 없음 | 생성됨 |
| 종이 직렬화 데이터 | 원본 동일 | 원본 동일 |
| Parts.valid 타입 오류 | 재현 | 재현되지 않음 |

진단 비교 5개 검사를 통과했다. 이는 실패 원인과 타입 교정 효과를 확인한 결과이며 제품 수정 완료를 뜻하지 않는다. 원본 실행은 표시 갱신을 시도하는 프레임마다 같은 오류가 반복된다.

## 최소 수정·회귀 요청

- 초기 접기 이력을 생성 시부터 `Array[Dictionary]`로 만든다. 프로젝트의 기존 typed 배열 패턴을 사용한다.
- `Parts.valid` 우회나 일반 `Array`로의 서명 완화로만 끝내지 않는다. 뒤따르는 `Model.pose`, `launch_frame` 등도 타입이 지정된 접기 이력을 받는다.
- 새 공원을 열자마자 I → 꺼내기 → 여러 프레임 손 표시를 검사한다. 그 전에 종이를 접거나 저장하여 초기 이력이 정규화되는 경로를 거치지 않는다.
- 같은 초기 색종이의 살펴보기, 준비/취소, 작업대 왕복을 확인한다. 종이의 모양·ID·수량은 유지하고 오류 로그가 없어야 한다.
- 기존 공원 테스트는 접고 보관한 기체를 꺼내거나 테스트용 종이를 먼저 대입한다. 초기 빈 이력 경로를 직접 다루는 회귀를 추가한다.

개발 범위는 초기 종이 상태와 이를 사용하는 공원 흐름이다. 비행 물리·용지 크기·준비 카메라·층 간섭 알고리즘 추가 변경은 요청하지 않았다.
