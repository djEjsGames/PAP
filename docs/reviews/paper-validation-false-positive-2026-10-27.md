# 종이 검증 실패 원인 분석

검토일: 2026-10-27. 제품 코드와 사용자 원본은 변경하지 않았다.

## 결론

제공 덤프 `pap_2026-10-27T16-43-07_56305654.json`의 보관 실패는 **6번째 접기의 경계 접촉을 층 관통으로 오인한 검증 오탐**이다. 실제 재료 손실이나 찢어짐, 마지막 날개 접기의 실패가 아니다.

- A4 21×29.7cm, 80g/m², 접기 8회와 뒤집기 3회, 최종 68면, IDLE 상태.
- `Presets._validate_state()`에서 종이/이력의 형식, 순서, 현재 형상 일치, 용지 메타데이터 검사를 통과한 뒤 `Dump.validate()`의 과거 층 간섭 검사에서만 거부된다.
- 총 재료 면적 0.062369996755109m². A4 원래 면적 0.06237m²가 보존되며 연결성·개별 면적 보존 오류도 없다.
- 1~5회와 7~8회 접기에는 층 간섭 보고가 없고, 6회차에만 4건이다. 이때 `single_layer=false`다. 이후 한 겹 접기 조작이 직접 원인은 아니다.

## 교차 검증

기존 `tests/validate_dump.gd`로 실패를 재현하고, 보관에 쓰는 `Presets._validate_state()`에서도 같은 문구를 확인했다.

> 종이 검증 실패: Recorded folds lift buried paper through stationary upper layers

문제로 지목된 이동 면과 고정 면은 접기선의 반대편에 있다. 경계 부근 좌표 오차는 약 2×10⁻⁹m 수준이다. `Paper.overlap_area()`가 사용하는 `Geometry2D.intersect_polygons()` 결과는 다음과 같다. 면 인덱스는 0부터 시작한다.

| 이동 층 → 고정 상부 층 | 현재 엔진 계산(m²) | 독립 배정밀도 볼록 다각형 교차 계산(m²) |
|---|---:|---:|
| 0 → 14 | 1.01397745×10⁻⁷ | 0 |
| 1 → 14 | 2.23226380×10⁻⁸ | 2.52718934×10⁻¹¹ |
| 1 → 15 | 2.23226380×10⁻⁸ | 2.70749996×10⁻¹¹ |
| 12 → 14 | 8.85920599×10⁻⁸ | 0 |

독립 계산은 외부 패키지 없이 Python의 배정밀도 실수로 Sutherland–Hodgman 볼록 다각형 교차를 수행했다. 알려진 사각형 겹침과 경계 접촉 2건의 자체 검사를 통과했다. 문제 4쌍의 실제 교차는 모두 **현재 MIN_OVERLAP_AREA=10⁻¹⁰m² 미만**이다. 허용 기준을 높이지 않아도 거부 대상이 아니다.

추가로 엔진에 입력하는 좌표만 1,000배 확대해 교차 면적을 계산한 뒤 환산하면 기존 결과보다 대폭 작아진다. 이는 경계에서 교차 계산의 수치 정밀도 영향을 받는다는 근거다. 단, 이 확대 기법만으로 전부 안정적으로 해결되지는 않으므로 그대로 제품 수정안으로 채택하면 안 된다.

## 접을 때는 허용되고 보관에서 실패하는 이유

1. `Paper.plan()`은 접기선의 움직이는 쪽에 있는 조각들에 대해 위층의 동반 이동을 계산한다.
2. 선 반대편에 남는 조각은 고정 면으로 유지한다. 경계를 공유하는 정상적인 분할이다.
3. 완성된 계획을 저장한 후 `Dump.validate()`는 `Paper.layer_obstructions()`로 모든 이동 면과 고정 상부 면을 다시 비교한다.
4. 이때 교차 계산이 경계에서 가짜 면적을 만들어 내므로, 정상적인 계획이 과거의 층 관통으로 판정된다.

덤프의 6회차 접기선과 방향으로 현재 `Paper.plan()`을 다시 호출해도 **비어 있지 않은 계획을 생성하고, 그 계획을 재검증하면 동일한 4건이 발생**한다. 이력 변조나 오래된 형식 문제로 설명할 수 없다.

최근 이동·카메라·복귀 UI 변경이 직접 원인이라는 근거는 없다. 실패 위치는 기존 종이 기하/저장 검증 경로다. 최초 발생 버전까지는 추적하지 않았다.

## 개발 수정 권고

- 단순히 저장 검증을 생략하거나 전역 허용 면적을 올리지 않는다. 실제 종이 관통 차단은 유지한다.
- 접기선 양쪽에 분리된 경계 접촉과 실제 면적 겹침을 구별하도록 공통 겹침 판정의 수치 안정성을 보강한다. 접기 허용과 저장 검증이 같은 결과를 내야 한다.
- `overlap_area()`는 층 동반 이동뿐 아니라 원본 재료 면 찾기에도 쓰이므로 호출 범위를 확인한다. 실제 면 분할·이력 보존은 유지한다.
- 이 덤프를 회귀 사례로 추가해 기존 이력이 보관 검증을 통과하는지 확인한다. A4의 거의 수직인 접기선과 경계 접촉, 용지 4종 크기 차이, 기존 `wing_layer_overlap.json`의 실제 관통 거부를 함께 검사한다.
- UX에서는 오류 발생 접기 번호와 이유를 한국어로 안내한다. 저장에 실패해도 편집 중인 종이와 되돌리기 이력을 유지한다. 내부 영어 문구만으로 정상 조작을 사용자의 실수처럼 보이게 하지 않는다.
