# HUD 개선과 무료 사운드 적용

2026-10-28. 결과창 가림과 투척 고도각 가시성을 개선하고, 확보한 CC0 음원을 실제 게임 이벤트에 연결했다. 커밋·푸시·배포는 하지 않았다.

## HUD와 입력

- 결과창은 일반 HUD보다 앞인 z=100 모달 계층에 표시된다. 전체 배경이 뒤쪽 GUI 클릭을 차단하며, 조준·휠·게이지 입력도 차단한다. 열린 뒤에는 진행 중 드래그를 중단한다. 닫기 버튼과 첫 Esc는 결과창만 닫는다. 공원의 명시적 B 복귀는 유지한다.
- 넓은 화면에서는 결과 패널을 우측 16px 여백에 배치한다. 640×360에서는 넓은 패널로 표시한다. 내용은 스크롤되고 복귀/재시도 버튼은 하단에 남는다. 공원의 복귀 버튼은 주 행동 색상으로 강조했다.
- 하단에 ‘투척 고도각’과 32px 도 단위 숫자, ± 버튼, 실제 입력 안내를 분리했다. 공원도 ↑↓ / ±를 park.view_angles.y에 연결하므로 다음 프레임에 값이 덮어써지지 않는다. 준비 중 우클릭 조준을 유지하고, 자세 조정창의 우클릭은 시점만 바꾼다고 구분한다. 강도/원점 단계에서는 고도각을 잠근다.
- 상단에서 좌우 yaw 목표 숫자를 제거하고 상태·거리·체공·용지와 보조 행동을 표시한다. 준비→강도→원점→비행→착지의 주 버튼과 안내를 유지했다.
- 하단 제어 영역은 166px이며, 기체 화면 맞춤은 실제 HUD 위의 안전영역을 사용한다. 4종 용지와 두 창 크기를 검사했다. 공원의 정후방·기본 15° 카메라 방향, 실제 발사 높이 1.7m, 20px 원점과 힘·편차 규칙 및 용지 물리는 유지한다.
- 새 HUD 배치에 맞춰 링 검사는 배치 완료 후 실제 GUI에 가리지 않은 위치를 선택한다. 정상적으로 잡은 링의 드래그가 HUD 위를 지나도 끊기지 않게 했으며, HUD 위에서 새 드래그를 시작하거나 모달 뒤에서 조작하는 것은 허용하지 않는다.

## 오디오 실제 적용

전역 Audio 자동 로드가 BGM 1개와 효과음 재생기 8개를 관리한다. 장면/기체 생성마다 오디오 서비스를 새로 만들지 않는다. 음악은 공원·작업대·관찰·비행 왕복 중 이어지며, 입력마다 재시작하지 않는다.

| 성공 이벤트 | 연결 |
|---|---|
| 접기 실제 확정 | bookFlip1 / bookFlip2 교대 |
| 뒤집기·펼치기 완료 | bookOpen |
| 실제 기체 release | card-shove-1 |
| 첫 논리적 착지 | card-place-2, 종료 중복 호출에는 재생하지 않음 |
| 같은 기체 회수 / 발견물 보관 성공 | cards-pack-take-out-1 |
| 보관함에서 손에 꺼내기 | card-slide-2 |
| 발견물 정리 성공 | confirmation_001, 돈 획득 효과 없음 |
| 실제 접지 이동 | grass 발걸음 2종 교대, 간격 0.4초 |
| 메뉴 열기·닫기 | open_001 / close_001 |
| 게이지 시작·강도 선택·실제 발사 타이밍 확정 | click_001 / select_001 / tick_001 |
| 도면 저장 / 작업대 보관 성공 | confirmation_001 |
| 저장 실패 / 막힌 투척 | error_002, 성공음 없음 |

발걸음은 정지·벽 막힘·창 열림 시 재생하지 않는다. 단순 관람 종료는 착지나 회수로 취급하지 않는다. 효과음 선택에 게임의 전역 난수를 소비하지 않는다.

Music / SFX 버스별 음량과 음소거를 ‘소리’ 설정에 제공했다. 각 화면의 기존 메뉴/도구에서 접근하며, Esc는 이 팝업만 닫는다. 값은 user://audio.cfg에만 저장한다. 초기 버스 음량은 음악 50%, 효과음 75%다. 플레이어 gain은 BGM −14dB, 일반 효과음 −10dB, 발걸음 −24dB로 여유를 뒀다.

사용 음원 17개만 assets/audio에 포함했다. Kistol의 Etirwer 루프와 Kenney 4개 팩은 모두 CC0다. 원본 음원을 가공하지 않았으며 BGM 파일명만 변경했다. 팩 전체·HTML·ZIP·미사용 음원은 build 밖으로 복사하지 않았다. [출처·파일·이벤트 목록](../../assets/audio/SOURCE.md), 각 License.txt를 보존했고 내보내기 포함 목록에도 추가했다.

누락/임포트 전 리소스가 있더라도 null.loop로 서비스가 중단되지 않게 보호했다. 실제 게임 시작 전 editor import를 완료하고 신규 시작을 확인했다. Dummy 드라이버에서는 들리지 않는 재생 객체를 생성하지 않고 이벤트 흐름만 유지해 종료 리소스 오류를 피한다. 웹에서는 첫 사용자 입력까지 BGM 시작을 기다리도록 했으나 브라우저 실행은 이번 범위에서 하지 않았다.

재생 직후 즉시 종료할 때 남던 OGG 객체 정리 경고도 확인했다. 창 닫기 요청에서는 재생을 중단하고 오디오 스레드가 처리할 0.1초를 둔 뒤 종료한다. GPU 통합 검사도 같은 정리 절차를 사용하며, 최종 78/0 로그에서는 종료 경고와 리소스 오류가 사라졌다.

| 전체 종이 회귀 — GPU | 16,368 통과 |

최종 로그에 SCRIPT ERROR / ERROR / WARNING은 없다. 새 검사는 결과창 뒤 실제 클릭·고도각·휠·발사 입력 차단, Esc 우선, 키 누름 유지, 결과창 아래 실제 비행·착지, 중복 release/착지/회수 방지, 저장 실패의 성공음 방지, 막힌 투척, 보행·벽 막힘·보관함 상태와 음량 분리·설정 저장을 포함한다.

실제 GPU 오디오 버스에 AudioEffectCapture를 붙여 확인했다. Music과 SFX 각각 62,976프레임이 캡처됐으며, Music peak≈0.09069 / energy≈35.13, 투척 SFX peak≈0.24739 / energy≈6.26으로 비무음 출력이다. BGM 위치는 약 0.726→1.730초로 진행했다. 해당 출력 검사에서 peak는 1 미만이다. 이 수치는 스피커 청감 평가나 모든 동시 효과음 조합의 클리핑 보장을 뜻하지 않는다.

## 사용자 확인과 남은 범위

준비 고도각 숫자를 보며 ↑↓ / ±와 우클릭 조준이 원하는 감각인지, 결과창이 앞에 표시되고 Esc 한 번으로만 닫히는지 확인하면 된다. 소리 메뉴에서 BGM과 효과음 크기를 따로 조절해 초기 믹스를 확인할 수 있다.

음량의 정밀 청감, 130초 음악 루프 경계 청감, 장시간 플레이와 브라우저 오디오 잠금 해제는 미검증이다. 웹 빌드·배포·커밋·푸시는 수행하지 않았다.
