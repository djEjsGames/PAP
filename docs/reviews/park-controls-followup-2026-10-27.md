# 공원 이동·준비 가림·착지 안내 교차검증 — 2026-10-27

## 사용자 피드백과 검토 범위

- WASD에 따라 캐릭터가 이동 방향을 바라보지 않는다. 카메라 기준의 이동 방향을 사용하기를 원한다.
- 투척 준비에서는 캐릭터 모델을 숨기거나 최소화해 비행기를 더 잘 볼 수 있어야 한다.

이번 기획 검토에서는 제품 코드를 수정하지 않았다. 최신 구현 소스, 실제 GPU 렌더링, 엔진 입력과 실제 착지, 개발 세션의 독립 진단을 대조한다. 기존 '준비에도 사람을 보여 준다'는 이전 기획안보다 이번 사용자 플레이 피드백을 우선한다.

## 1. 이동: 벡터는 이미 카메라 기준, 몸 회전이 미연결

현재 수평 이동은 `Basis(UP, view_angles.x) * input.normalized()`로 계산된다. 하지만 몸의 yaw는 입력과 관계없이 매번 `view_angles.x`로 정해진다.

| 입력 | 이동 방향과 캐릭터 루트 전방의 차이 |
|---|---:|
| W | 0° |
| A / D | 90° |
| S | 180° |
| W+D | 45° |

위 결과는 카메라0/90°와1280×720/640×360에서 같았다. 따라서 이동 벡터 계산을 중복 추가하기보다 **캐릭터 전방을 이동 입력 방향에 연결**하는 것이 수정 지점이다. 기존 검사는 W에서 run 클립으로 바뀌는지만 확인해 옆/뒤 이동의 시각적 방향 불일치를 놓친다.

수정 기준:
- 이동 입력을 카메라의 수평 전방/오른쪽으로 계산하는 기존 원칙을 유지하고, 캐릭터는 그 방향으로 돌아서 이동한다. 대각 속도는 정규화한다.
- 카메라 pitch를 이동에 섞어 땅에서 뜨거나 내려가지 않게 한다. 입력이 없으면 마지막 몸 방향을 유지하고 카메라만 둘러볼 수 있게 한다.
- 회전은 짧고 자연스럽게 따라가며 충돌/정지에서 떨리지 않아야 한다. 충돌 처리와 조준값을 몸 회전에 종속시키지 않는다.
- 소지 기체와 손 목표도 몸 회전에 맞는지 확인한다. 몸만 돌고 손/기체는 카메라 기준 위치에 남는 현상을 새로 만들지 않는다.
- 게이지 시작 후 위치/조준 고정, 준비의 시선 기반 목표 방향과 기존 월드 이동 입력 분리를 유지한다.

## 2. 준비: 중심 좌표 검사는 통과하지만 캐릭터가 시야를 차지함

기체 COM은 두 해상도 모두 세로48%로 유지된다. 그러나 기본 색종이 준비 PNG에서 얼굴·어깨·손이 기체 주변을 크게 차지하고 손이 일부 면을 덮는다. 작은 창에서는 비행기 형태를 읽기 더 어렵다.

측정 시 기본 카메라→기체 거리는1280에서약0.45m,640에서약0.83m였고 `clear_held=false`였다. 부분 투명화는 거리0.35m 미만에서만 켜지므로 기본 구도의 가림을 해결하지 못한다. 준비 카메라는 목표 yaw보다−35°인 어깨 구도다. COM/HUD 영역과 손 접촉 오차의 기존 검사는 **사람에 의한 가림과 화면 점유**를 확인하지 않는다.

- 기준 화면: `ready_character_1280.png`, `ready_character_640.png`.
- 캐릭터만 임시로 숨긴 비교: `ready_character_hidden_diagnostic_only_1280.png`, `_640.png`. 같은 종이·카메라·물리 조건에서 형태가 명확해지는 것을 확인했다. 이는 수정 완료 화면이 아니다.

수정 기준:
- 탐색에서는 캐릭터를 보이고, **투척 준비/게이지에서는 캐릭터 시각 모델 숨김을 기본**으로 한다. 애매한 부분 투명화보다 기체를 읽을 수 있는 상태를 우선한다.
- 충돌체·플레이어 위치·실물 기체와 지면+1.7m 발사 높이는 그대로 유지한다. 작은 종이를 크게 보이게 하려고 물리 크기를 바꾸지 않는다.
- 사람을 담기 위한35° 어깨 보정의 필요성을 줄이고 기체와 실제 발사 방향을 함께 읽기 쉬운 구도로 맞춘다. 카메라 때문에 실제 목표 방향·고도각을 바꾸지 않는다.
- 투척/준비 취소/관람 종료/수치 오류 복구에서 캐릭터 시각 상태가 정상으로 돌아와야 한다. 숨김이 다음 탐색까지 남지 않아야 한다.
- 자세/날개 조정·네 용지·줌·작은 창에서도 기체 형태와 화살표가 보이는지 확인한다.

## 3. 착지: 키는 작동하지만 다음 행동이 비활성 안내로 남음

두 해상도에서 실제 착지를 확인했다(예시40%/무풍,약4.37m·2.18초). 착지 뒤 `active_flight`는 계속 관람 상태다.

- 주 버튼은 **disabled=true**, 문구는 '착지 · 공원으로 돌아가 회수하세요'. 실행 행동이 아닌 비활성 안내다.
- 상단에는 '공원으로 · 관람 종료 [B]'가 남지만 하단 주 행동에서 이어지지 않는다.
- 옆의 '취소 [Esc]'도 `gauge_stage==0`이라 비활성이다. 실제 Esc 키는 관람을 종료할 수 있어 표기의 의미와 상태가 맞지 않는다.
- 하단 설명에는 **↑↓ 고도각**이 다시 나타난다. 월드 투척에서 상하키 목표 조절은 사용하지 않으므로 잘못된 모드 안내다.
- 실제 입력 검사에서 결과 팝업을 연 뒤 첫 Esc는 결과창을 닫고, 다음 Esc는 공원으로 복귀했다. 이 팝업 우선순위는 유지해야 한다.

수정 기준:
- 실제 착지 때 게이지 영역을 **착지 결과 요약 + 활성 주 행동 '공원으로 돌아가기 [B / Esc]'**로 전환한다. 마우스 클릭으로도 같은 기능을 실행할 수 있게 한다.
- 준비/강도 선택/비행/착지의 문구와 활성 상태를 분리한다. 끝난 게이지·작동하지 않는↑↓설명·비활성 취소는 착지 상태에 남기지 않는다.
- '공원으로 돌아가 착지 표식을 따라가면 E로 회수'를 짧게 안내한다. 이 동작은 시점 복귀이며 기체를 자동 회수하거나 플레이어를 착지점으로 순간이동시키지 않는다.
- 비행 중에도 관람 종료를 알 수 있게 하고, 실제 착지 후의 주 행동을 더 선명하게 한다. 착지 즉시 강제 시점 복귀는 하지 않는다.
- 결과 팝업 Esc닫기 우선순위와 게이지 취소를 보존한다. 키홀드/클릭/중복 종료로 결과 중복·아이템 복제·자동 재발사를 만들지 않는다.
