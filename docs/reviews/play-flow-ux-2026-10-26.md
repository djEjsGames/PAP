# 반복 플레이 흐름 UX 검토 — 2026-10-26

후속 개발 반영과 검증은 [반복 플레이 UX 구현 기록](play-flow-implementation-2026-10-26.md)을 참고하세요. 아래는 구현 전 기획 검토 기록입니다.

## 판단과 범위

사용자는 접기 해석과 비행 물리가 현재 개인 플레이에서 큰 장애는 아니며, 버튼과 디자인을 읽고 찾아가는 구간이 흐름을 끊는다고 평가했다. 최신 화면과 상태 전환을 확인한 기획 판단도 **이번 우선순위는 반복 플레이의 행동 연결과 정보 위계**다.

물리·종이 해석·발사 판정 규칙·새 콘텐츠를 이번 개편의 대상으로 삼지 않는다. 접기 → 선택적인 부위 확인/저장 → 날리기 → 결과 확인 → 다시 날리기/접기 수정의 흐름을 다듬는다.

## 개발 요청: 최소한의 완성된 개편

### 1. 하단의 고정된 주요 행동 영역

접기와 비행에 공통된 하단 행동 영역을 두고, 주요 버튼의 위치와 강조를 유지하며 상태에 따라 행동 이름을 바꾼다. 화면마다 여러 대표 버튼을 새로 찾게 하지 않는다. 현재 게이지의 왕복·원점 판정은 그대로 사용한다.

| 상태 | 주 행동/상태 표시 | 보조 행동 |
|---|---|---|
| 접기 대기 | 날려보기 | 도면 저장, 부위 확인 |
| 비행 준비 | 던지기 준비 · Space/Enter | 접기 수정, 자세/날개 조정 |
| 강도 선택 | 강도 결정 · Space/Enter | 취소 |
| 강도 확정 후 끝점 진행 | 끝점까지 진행 후 돌아오는 중(입력 대기 이유) | 취소 |
| 원점으로 복귀 | 원점에서 던지기 · Space/Enter | 취소 |
| 비행 중 | 비행 중 · 거리/체공시간 | 관람과 카메라 조작, 결과 |
| 착지/종료 | 다시 던지기 · Space/Enter | 접기 수정, 결과 |

- 착지 후 '다시 던지기' 한 번으로 발사 위치 복귀와 새 강도 게이지 시작을 이어 간다. 위의 재시도와 아래의 시작을 연달아 누르게 하지 않는다. 실제 투척은 기존 최종 타이밍 입력 후 이루어지며 자동으로 재발사하지 않는다.
- R의 기존 위치 복귀 기능은 보존하되 '발사 위치로'처럼 결과를 알 수 있는 이름의 보조 기능으로 구분한다.
- 비행 중 입력을 막을 때도 왜 비활성인지 상태가 읽혀야 한다. 착지 후에는 직전 거리·체공시간을 주요 행동 근처에 짧게 보여 완료를 알린다. 상세 결과 팝업을 자동으로 열지 않는다.
- 주요 버튼은 채운 강조색, 보조 버튼은 낮은 강조, 상태는 텍스트/배지로 구분한다. 단축키는 보조 표기로 남긴다. 글자를 줄이기 위해 의미 없는 아이콘만으로 바꾸지 않는다.
- 640×360에서 상단 도구가 줄바꿈돼도 주요 행동 위치는 유지한다. 하단 행동 영역·바람·결과창을 서로 침범하지 않게 한다. 드래그 중 종이 투영을 고정하는 기존 정책도 보존한다.

### 2. 부위 확인을 다음 행동으로 연결

- 유효한 후보에서 **확정하고 날려보기**를 제공해 한 번에 확정·패널 닫기·비행 준비로 이동하게 한다. 접기 중 사용할 **확정하고 계속 접기**도 보조 행동으로 둔다. 기존 단순 확정 기능과 결과가 충돌하지 않게 한다.
- 작은 창에서 확정과 닫기는 항상 보이는 고정 하단에 둔다. 내용만 스크롤한다.
- 공간이 좁으면 '날개 1 / 날개 2 / 손잡이' 역할 선택과 현재 역할의 후보만 보여 주는 구성을 사용한다. 3개 역할의 버튼·선택상자를 전부 세로로 쌓아 완료 행동을 숨기지 않는다.
- 강조·미리보기·후보 번호는 유지하되, 첫 안내는 '색으로 표시된 날개와 손잡이를 확인하세요'처럼 행동을 설명한다. 미확정도 자유롭게 날릴 수 있다는 원칙을 유지한다.

### 3. 왕복 시 세션 맥락 유지

- 비행 → 부위 확인/접기 → 비행의 왕복에서 목표 고도각, 풍속·풍향, 마지막 강도, 카메라 시점·줌, 최근 비행 기록을 유지한다. 기존 화면 인스턴스가 사라져도 사용자 의도와 기록이 함께 사라지지 않게 한다.
- 새 종이·프리셋 불러오기처럼 기체가 달라지는 경우는 구분하고 이전 발사 기록의 조건을 소급 변경하지 않는다. 기록을 이어 보여 준다면 '기체 수정 전' 등 비교 대상을 혼동하지 않는 표시를 둔다.
- 사용자가 확정한 기존 자세/날개는 같은 기체의 단순 확인 왕복에서 유지한다. 실제 접기 변경 후에도 유효한지 기존 검증을 거쳐 기본 자세로 돌아갈 필요가 있으면 짧게 알린다.
- 게이지가 동작 중인 상태 자체는 왕복/재개하지 않는다. 복귀 시 준비 대기로 정리하고, 자동 빗맞음 예약도 남지 않게 한다.
- 이는 실행 중 세션의 맥락 유지 범위다. 영구 비행 기록 저장·새 기록 관리 화면·클라우드는 추가하지 않는다.

### 4. 결과·저장 이후의 출구

- 결과는 거리·체공시간을 먼저, 강도·목표/실제 고도각·편차·바람·날개는 그 아래 보조 정보로 배치한다.
- 결과창에서 '다시 던지기' 또는 '접기 수정'으로 바로 이어 갈 수 있게 한다. 다음 행동을 누르면 팝업 닫기를 별도로 요구하지 않는다. 패널 안 명시적 행동만 실행하고, 일반 키 입력이 뒤로 새어 재발사하지 않게 한다.
- 타이밍 조작 도중 결과를 여는 동작이 게이지를 조용히 취소하지 않게 한다. 가장 작은 대응은 게이지 진행 중 결과 열기를 비활성화하고 상태 이유를 표시하는 것이다.
- 프리셋의 사용자용 이름은 '내 도면' 또는 '도면 보관함'처럼 기능을 알 수 있게 한다. 저장 성공은 비차단 알림으로 전달하고, 저장 후 계속 접기/날려보기로 바로 이어 갈 출구를 제공한다.
- 덮어쓰기·현재 종이 교체 등 데이터 손실 방지 확인은 보존한다. 저장이나 부위 확정을 날려보기의 필수 관문으로 추가하지 않는다.

## 완료 기준과 검토 자료

1. 첫 화면에서 주요 날려보기 행동이 다른 도구보다 먼저 식별된다. 작은 창의 줄바꿈이 주 행동을 숨기거나 옮기지 않는다.
2. 부위 패널의 완료·닫기 행동은 640×360에서도 스크롤 없이 보인다. 유효 후보의 확정→날리기는 한 동작이다.
3. 착지 뒤 다시 던지기는 한 입력으로 새 게이지까지 이어지고, 별도 위치 초기화 입력이나 팝업 닫기를 요구하지 않는다.
4. 같은 기체의 부위 확인/접기 화면 왕복에서 설정·카메라·최근 기록이 유지된다. 기체 변경 뒤 잘못된 지정은 사용하지 않는다.
5. 게이지 규칙(고도각 사전 설정, 끝점 진행 후 복귀, 20px 원점, 고도각 편차·자동 빗맞음), 바람 표시와 카메라 조작은 변경하지 않는다.
6. 새 종이/불러오기/저장/취소/Esc/실제 키 입력에서 의도하지 않은 발사·데이터 덮어쓰기·입력 누수가 없다.
7. 개발 세션에서 1280×720와 640×360의 접기→부위 확인→준비→게이지→실제 착지→결과→재시도→접기 복귀 순서 PNG와 동작 검증을 남긴다. 완료 후 다시 기획·디자인 관점으로 결과를 검토한다.

이번에는 제품 코드를 수정하지 않았고, 위 범위의 개발 요청 문서를 작성했다. 디자인이 개선됐다는 최종 판단에는 구현 후 화면과 사용자 플레이 체감 확인이 필요하다.
