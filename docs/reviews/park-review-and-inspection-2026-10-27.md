## 1. 공원 HUD와 가독성

- 현재 두 버튼+나열 문장을 작은 **현재 상태 영역 / 근처 행동 안내 / 보관함 진입**으로 구분한다. 손에 든 기체(또는 없음), 보관 개수, 지금 가능한 행동을 먼저 읽게 한다.
- 상태 문자를 기본16px 이상, 주 행동/대상 안내를18–20px 수준으로 시작한다.640창에서 겹침을 피하려고 글자를 다시 작게 줄이지 않는다. 긴 조작 설명은 상황별 한 줄 또는 도움말로 분리한다.
- 밝은 하늘·길·탁자 위에서도 읽히도록 글자 뒤의 짙은 반투명 바탕/패딩 또는 얇은 외곽선을 적용한다. 작업대 강조와 안내의 명도가 같지 않게 한다.
- 같은 대상의 거리 표식과 행동 안내가 겹치지 않게 대상 근처에 묶는다. 일반 기체ID는 보조로 두고 이름/행동/거리의 순서를 정리한다.
- 주요 입력은 기존 반복 플레이 개편처럼 안정된 하단 행동 영역을 활용한다. 보조 상태와 버튼이 장면을 덮지 않게 한다. 미니맵·체력·임의 목표점수·미구현 보상 수치는 추가하지 않는다.
- UI를 채워 보이게 만드는 것보다 '지금 무엇을 들었고, 여기서 무엇을 할 수 있는지'를 선명하게 한다. 바람을 표시할 때는 실제 적용 값과 일치시킨다.

## 2. 투척 준비 구도

- **실제 발사 높이 지면+1.7m, 종이 실제 크기, 질량/관성은 유지**한다.
- 기본 준비에서 기체가 화면 중앙 부근 또는 약간 아래의 안전 영역에 놓이게 카메라의 초점/기준 높이/거리 관계를 맞춘다. 기본 목표는 세로45–65% 영역이며, 상단 정보나 하단 게이지에 가리지 않는 것이 우선이다.
- 근접/원거리 줌, 시선−10°/0°/+15°, 큰 신문지/4절과 작은 색종이,1280/640에서 정점 투영 영역을 검사한다. 가림/화면 밖 배치를 폰트나 종이의 물리 스케일 변경으로 숨기지 않는다.
- 조준 방향과 실제 초기 속도는 기존처럼 일치해야 한다. 화면 구도를 바꿨다고 기체/발사 방향을 따로 위로 돌리지 않는다. 물리 위치와 표시용 모델을 멀리 분리해 발사 순간 순간이동시키지 않는다.
- 인간형 적용 후 손에 든 상태·준비·발사·비행 관람의 전환을 함께 확인한다. 지금처럼 캐릭터 시각 모델을 무조건 숨기는 처리만으로 소지감을 대신하지 않는다. 필요한 가림 처리는 카메라 근접 상황에서만 최소 범위로 둔다.

## 3. 발견물 살펴보기

### 흐름

새 발견물에 접근 → 집기 → **살펴보기 자동 진입** → 회전/펼쳐보기 → 보관하기 / 다시 놓기 / 정리하기.

새 발견물의 가치에 쓰레기/유용함/희귀함 등급을 붙이지 않는다. 형태와 실제 용지 정보를 보고 처리 방향을 결정하게 한다. 이미 자신이 던지고 확인한 기체는 반복 플레이를 위해 빠른 회수를 유지하고, 보관함의 살펴보기로 같은 관찰 화면을 다시 열 수 있도록 하는 것을 기본안으로 둔다.

### 표시와 조작

- 화면의 가장 큰 영역에 실제3D 모델을 표시한다. 현재2D 평면 그림을3D 회전하는 것처럼 흉내 내지 않는다. UI는 이름·용지 종류·실제 크기·한 장 무게 중심이며 접기 횟수 등은 보조 정보다.
- **왼쪽 드래그는 모델 회전, 휠은 관찰 확대/축소**, 원래 시점으로 돌아가기를 제공한다. 비행 준비의 일반 드래그 기체 회전 금지는 유지하며 관찰 모드에만 이 조작을 허용한다.
- 회전/확대/펼침은 표시용 복사본에서만 한다. 실제 기체의 faces/history/부위 지정/날개 각도/자세/물성, 저장 도면, 발사 결과는 바뀌지 않는다.
- 유효한 날개 부위 지정이 있으면 그 축을 우선 사용해90°로 펼친 모습을 기본 관찰로 제공하고 '접힌 모습 / 펼친 모습'을 전환할 수 있게 한다.
- 부위 지정이 없으면 기존 자동 후보와3D 연결 검증을 거친 뒤 미리보기를 제공한다. 유효한 날개 축이 없는 종이/다른 물건에는 억지로 날개를 만들지 않는다. 마지막 두 접기 휴리스틱을 외형 인식 기능으로 설명하지 않는다.
- 크기가 다른 용지도 화면에 맞게 관찰 카메라만 조절하고, 실제 치수를 바꾸지 않는다. 큰 종이와 작은 종이의 물리 크기는 수치로 확인할 수 있어야 한다.

### 처리와 데이터 보호

- 집은 순간에는 같은 ID를 관찰 중인 상태로 예약한다. 보관 확정 전 인벤토리에 자동 저장하거나 세계·인벤토리 양쪽에 중복으로 존재하지 않게 한다.
- **보관하기**는 같은 실물을 보관한다. **다시 놓기/Esc**는 원래 위치·기체 상태로 복귀한다. **정리하기**는 다른 두 행동과 시각적으로 구분해 정리한 발견물로 기록한다. 이번에는 봉사 보수·가격을 추가하지 않는다.
- 보관함에서 관찰을 열었다면 Esc/닫기는 보관함/원래 소유 상태로 돌아간다. 보관함 물건을 뜻하지 않게 바닥에 내려놓지 않는다.
- 접는 방법을 남기는 기능은 기존 내 도면 저장을 재사용하는 보조 행동으로 연결할 수 있다. 정리와 도면 참고가 강제로 배타적 선택이 되지 않게 한다.
- 관찰 중에는 캐릭터 이동·월드 시점·발사 입력을 막고 배경의 다른 비행은 유지한다. 문을 연 입력·키홀드·Esc·중복 클릭으로 바로 처리/폐기/발사가 실행되지 않게 한다.

## 개발 순서와 완료 근거

1. HUD 크기/대비/상태 위계와 대상 안내 중복을 수정한다.
2. 물리 높이1.7m를 보존하며 준비 카메라를 고친다.
3. 선정 캐릭터를 실제 적용하고 소지/준비 구도를 재확인한다.
4. 발견물3D 관찰·원본 불변 펼침·처리 선택을 최소 루프로 연결한다.

완료 후1280×720와640×360에서 밝은 하늘/탁자/길 위 HUD, 준비 pitch와 줌별 기체 표시, 캐릭터 idle/이동/소지, 발견물 집기→회전→펼침→각 처리→재회수 화면을 제출한다. 카메라는 COM/기체 화면 영역과 HUD 비겹침, 관찰은 원본 직렬화 불변과 단일 ID 소유, 각 처리/취소/중복입력/회수 보존을 검사한다. 기존 용지·가이드·접기·게이지·물리·카메라·실물 루프를 회귀 확인한다. 웹은 기존 환경에서 키·드래그·휠·포커스·FBX 가져온 결과의 표시를 확인하고 별도 공개 배포는 하지 않는다.

이 문서는 실제 화면과 독립 측정에 기반한 개선 요청이다. 아직 개선 후의 사용자 체감·캐릭터 제품 적용을 검증한 결과는 아니다.
