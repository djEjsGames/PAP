# HUD 개편과 무료 사운드 첫 적용

2026-10-28. 사용자 요청에 따라 기획 세션에서 현재 HUD를 검토하고 무료 음원을 확보했다. 개발 세션에는 실제 HUD·오디오 적용을 요청했다. 이 문서는 적용 기준이며 완료 보고와 구분한다.

## HUD: 기체와 다음 행동을 바로 읽을 수 있게

실제 GPU 화면 1280×720/640×360에서 결과 창이 상단 메뉴와 수치 줄에 가려지는 것을 확인했다. `results_panel`의 형제 순서는1, `topbar`는3이고 둘 다 z=0이다. 결과 창은 y=12에서 시작해 상단 메뉴와 수치 줄 영역에 겹친다. 글자 크기만 바꿔 해결할 수 있는 문제가 아니다.

공원 고도각은 우클릭 시선으로 정하지만 작은 문장과 상단의 `목표 0° / -12°`에 섞여 있다. ↑ 입력 전후도 -12°로 같았다. 공원과 독립 비행 화면의 입력이 다르므로 설명과 실제 입력을 먼저 일치시킨다.

| 영역 | 개편 기준 |
|---|---|
| 상단 | 현재 상태와 결과/조정/복귀 등 보조 행동을 간결하게 배치한다. 긴 기체 정보는 주 행동보다 덜 강조한다. |
| 결과 팝업 | 넓은 창에서는 기존 요청대로 오른쪽에 배치하고 상단을 포함한 일반 HUD보다 앞에 표시한다. 제목·닫기·스크롤·복귀 동작이 가려지지 않아야 한다. 뒤 버튼 클릭·조준·게이지 입력이 새지 않아야 한다. Esc 첫 입력은 창만 닫는다. 결과 창 때문에 실제 월드 비행을 멈추지 않는다. |
| 고도각 | 준비 하단에 ‘투척 고도각’과 **큰 도 단위 숫자(권장28px 이상)**를 따로 표시한다. 기체 자세 각도와 구분한다. 조작 안내를 바로 옆에 두고, 큰 숫자를 보고 변화와 잠금 상태를 알 수 있게 한다. |
| 고도각 입력 | 기존 공원 시선 조준을 유지한다. ↑↓ 또는 ± 직접 조정을 추가한다면 같은 조준값에 연결해 다음 프레임 `_read_target()`에 덮어쓰이지 않게 한다. 별도 좌우 방향 조작은 만들지 않는다. |
| 게이지 | 준비→강도 확정→원점 입력→비행→착지마다 상태와 주 버튼 문구를 바꾼다. 큰 고도각과 게이지가 서로 공간을 빼앗지 않게 한다. |
| 착지 | 활성 복귀 버튼과 짧은 거리·시간·회수 안내를 유지한다. 결과 창은 선택적으로 열고 닫는다. |
| 바람 | 우측 하단을 유지하되 고도각/게이지/결과 팝업에 가려지지 않게 배치한다. 작은 창에서는 글자 축소보다 정보 배치를 조정한다. |

변경하지 않을 기준은 힘·원점 입력 규칙과20px 판정, 카메라 정후방/15° 기본 구도, 지면+1.7m 발사, 용지·물리, 실제 기체의 소유/회수 흐름이다. 새 HUD가 기체를 가리면 준비 카메라의 안전 영역을 새 HUD 크기에 맞춰 계산한다.

수정 전 근거는 `build/hud_audio_review_20261028/before/`의 준비·결과 PNG와 `hud_measurements.json`에 보존한다. 작은 창 결과 화면은 닫기와 결과 첫 문장이 실제로 가려져 있다.

## 무료 음원 선정

공원에서 접고 날리는 활동에 맞춰 어쿠스틱 기타1곡과 짧은 종이·카드·UI·발걸음 효과음을 초기 소스로 정했다. 아래 공식 배포 페이지에서 CC0를 확인했고 Kenney 네 팩은 동봉 `License.txt`도 확인했다. 곡·팩 전체가 아닌 실제 사용 파일만 제품에 포함한다.

| 소스 | 작가 | 라이선스 | 선택한 용도 |
|---|---|---|---|
| [Etirwer](https://opengameart.org/content/etirwer) | Kistol | CC0 | 기타 루프 BGM, 130.234초 |
| [RPG Audio](https://kenney.nl/assets/rpg-audio) | Kenney | CC0 | 접기·뒤집기·펼침의 종이 질감 |
| [Casino Audio](https://kenney.nl/assets/casino-audio) | Kenney | CC0 | 종이 투척·착지·집기·꺼내기용 카드 Foley |
| [Interface Sounds](https://kenney.nl/assets/interface-sounds) | Kenney | CC0 | 창 열기/닫기, 게이지 확정, 저장 성공·실패 |
| [Impact Sounds](https://kenney.nl/assets/impact-sounds) | Kenney | CC0 | 낮은 잔디 발걸음 |

크레딧이 필수는 아닌 소스들이지만 작가·출처·라이선스·원본 파일명·사용 이벤트·가공 유무를 함께 보존한다. BGM은 공식 페이지의 라이선스와 작가 정보를 기록하고, Kenney는 각 동봉 라이선스 원문도 포함한다.

다운로드·라이선스 근거와 원본17파일은 `build/hud_audio_review_20261028/`에 있다. `download_manifest.json`에 공식 원본 URL, SHA256, 크기를 기록했다. `*_source.html`은 선택 당시 근거다. 전체팩 ZIP과 HTML은 게임에 포함하지 않는다.

## 음량·재생 기준

- BGM과 효과음의 음량·음소거를 간단히 분리 제공한다. 옵션 변경은 장면 왕복에도 유지한다.
- BGM은 단일 인스턴스로 유지해 창·장면·복수 기체마다 중복되거나 처음부터 다시 시작하지 않는다.
- BGM은 행동음 뒤로, 발걸음은 종이·투척보다 낮게 둔다. 최초에는 과도한 소리를 피하는 값으로 시작한다.
- 17파일 모두 디코딩·유한 샘플·유효 길이·비무음을 확인했다. `audio_measurements.json`에 길이와 peak/RMS를 남겼다. 압축 복원 피크가 일부0dBFS를 넘으므로 플레이어 음량에 여유를 둔다. 특히 bookFlip1(+0.47dBFS), error002(+0.58dBFS)는 감쇠 없이 크게 재생하지 않는다.
- 파일별 실제 청감과 최종 믹스는 사용자가 들어보며 조정할 단계다. 수치 분석만으로 최종 음질·분위기 검수를 완료했다고 하지 않는다.

## 개발 완료 확인

- 1280×720/640×360 준비·게이지·실제 착지·결과 열린 화면을 GPU로 확인한다.
- 결과 창을 열고 상단·기체 영역을 눌러도 뒤 행동이 실행되지 않으며 Esc 우선순위가 유지된다.
- 공원과 독립 비행 화면 모두 고도각 표시와 실제 입력값·발사 기록이 일치한다. 게이지 진행 중 잠금이 유지된다.
- 음원 임포트와 실제 재생, 성공당1회, BGM 단일성·연속성, 음량/음소거, 초기 색종이 꺼내기와 반복 회수의 기존 회귀를 확인한다.
- 실패·취소·강도 선택만으로 투척/획득 성공음이 나지 않아야 한다. 같은 착지에서 결과 레코드나 소리가 중복되지 않아야 한다.
- 브라우저는 첫 사용자 입력 전 자동 재생 제한을 고려하되 검증하지 않은 환경은 미검증으로 남긴다. 커밋·푸시·공개 배포는 요청 범위에 포함하지 않는다.

## 기획 세션 독립 확인

구현 중후반의 GPU 화면과 오디오 경로를 별도로 확인했다. 개발 세션의 최종 통합 결과와 함께 판단한다.

- 1280×720/640×360 준비·결과 화면에서 결과가 상단 HUD 앞에 표시되고 넓은 창에서는 오른쪽에 배치된다. 고도각은32px로 분리됐으며, 실제 ↑ 입력 후 -12°→-11°로 바뀌었다. 최종 캡처 로그에 오류가 없다.
- 중간 캡처의 OGG 미임포트 오류는 임포트 후 재실행에서 사라졌다. 수정 전 화면은 `before/`, 최종 준비/결과 화면은 확보 폴더의 `ready_*.png`, `results_*.png`다. 결과 패널이 별도 오버레이의 자식이 되었으므로 수정 전후의 단순 형제 순서 숫자만으로 전경 순서를 비교하면 안 된다.
- `check_sound_settings_ui.gd`의 GPU3검사가 통과했다. 작은 창에서 실제 소리 버튼→설정 팝업→Esc를 확인했으며, 팝업의 슬라이더·음소거·닫기가 잘리지 않고 Esc가 투척 준비까지 종료하지 않는다. `sound_settings_640.png`에 화면을 남겼다.
- `check_audio_mix.gd`로 실제 GPU 실행 중 Music/SFX 버스에 AudioEffectCapture를 연결했다. Music64,000프레임 peak0.09069·energy34.04, 투척 SFX63,488프레임 peak0.24739·energy6.26으로 비무음 출력이 확인됐다. BGM 재생 위치는0.801→1.814초로 진행됐다. 해당 진단 프로세스 안에서 버스만 일시 조정했고 사용자 설정 파일은 바꾸지 않았다.
- 파일의 디코딩과 실제 믹서 출력은 확인했지만 사람의 청감·반복 피로·최종 음량 취향까지 확인한 결과는 아니다.

## 구현·회귀 결과 확인

개발 세션에서 결과 전경 모달과 우측 배치, 큰 고도각·↑↓/± 연동,17개 음원의15종 효과음 이벤트와 단일 BGM, Music/SFX별 음량·음소거를 적용했다. 소리 버튼은 공원·접기·관찰·비행에서 접근한다. [실제 사용 파일과 출처](../../assets/audio/SOURCE.md)를 프로젝트에 남기고 내보내기에도 라이선스 파일을 포함했다.

기획 세션에서 개발 로그를 읽어 확인한 결과는 전체 종이 헤드리스15,662개·GPU16,368개 통과, 새 HUD/오디오 헤드리스77개·GPU78개 통과, 기존 공원 검토GPU356개·조작34개·반복흐름90개·초기 색종이Mono50개 통과다. 헤드리스는 Dummy 오디오이고 실제 재생을 확인하는 GPU 조건에서 검사 하나가 추가된다. 독립 기획 진단의 실제 믹서·설정 UI 결과는 위 항목과 별개다.

중간 전체 회귀에서 결과 Esc와 회전 링 입력에 문제가 발견돼 수정했다. 새 HUD에 가린 좌표를 선택하던 테스트는 실제 노출된 링 구간을 선택하게 바꿨고, 이미 잡은 링이 HUD 위를 통과할 때 드래그가 끊기는 실제 입력 경로도 보완했다. HUD 위에서 새 조작을 시작하거나 결과 뒤를 조작하는 것은 계속 차단한다.

중간 GPU 통합 로그에는 기능 검사78/0 뒤 종료 시 리소스 정리 경고가 관찰돼 추가 확인했다. 개발 세션이 종료 전 재생 중단과 오디오 스레드 정리 대기를 보완했고, 최종 GPU78/0 로그에서는 경고·오류가 사라진 것을 확인했다. [최종 구현·검증 기록](hud-audio-implementation-2026-10-28.md)을 적용 완료 기준으로 사용한다. 사람의 청감·브라우저 실행·공개 배포는 이 결과에 포함하지 않는다.
