# 종이 경계 접촉 검증 오탐 수정

2026-10-27. 제공된 A4 8회 접기 도면은 원본 형상·접기 이력·용지·비행 부위·기준점을 바꾸지 않고 보관할 수 있다. 저장 검증을 생략하거나 MIN_OVERLAP_AREA=1e-10m²를 높이지 않았다.

## 판정 변경

`scripts/paper_geometry.gd`의 공통 `overlap_area()`를 수정했다. 호출 경로는 접기 계획에서 위층 동반 이동 결정, 과거 계획의 층 간섭 검사, `_material_source()`의 원본 재료 면 매핑이다.

1. 볼록 면의 경계 변을 기준으로 양쪽 다각형을 검사한다. 좌표 크기에 비례하는 float32 해상도와 외적 계산의 불확실성 범위에만 걸친 접촉은 실제 겹침과 구분한다. 면적 허용치를 일괄 상향하는 방식이 아니다.
2. `Geometry2D.intersect_polygons()` 대신 볼록 다각형 클리핑을 사용한다. 교차점은 PackedFloat64Array에 보관해 중간 계산을 float32 Vector2로 다시 반올림하지 않는다. 클리핑은 양쪽 꼭짓점 순서를 모두 지원한다.
3. 입력 좌표 해상도보다 짧은 거의 중복된 변은 분리축 및 클리핑 경계로 사용하지 않는다. 전체 회귀에서 과거 도면의 이런 변이 재료 매핑을 -1로 만들던 사례를 발견해 보강했다. 저장된 꼭짓점을 삭제하거나 위치를 바꾸지는 않는다.

좌표 불확실성은 `u = max(abs(input coordinates)) × 2^-23`, 변 벡터 `(dx,dy)`와 점 상대 벡터 `(rx,ry)`의 외적 판정 범위는 `2u(|dx|+|dy|+|rx|+|ry|)+8u²`를 사용한다. 거의 중복된 변의 기준은 양 끝 좌표 해상도의 2배다. 모든 정밀도 처리는 겹침 질의 내부에서만 적용된다.

이 방식의 전제는 현재 종이 시스템처럼 직사각형을 직선으로 나누어 만든 볼록 면이다. 향후 오목한 면을 직접 도입하면 볼록 분할 또는 별도 교차 처리가 필요하다. 좌표 해상도 수준의 극히 얇은 침범은 경계 접촉과 구분할 수 없다는 수치 한계가 있다. 좌표 해상도를 충분히 넘고 기존 면적 기준보다 큰 작은 실제 겹침은 별도 회귀로 검출을 확인했다.

`scripts/paper_dump.gd`의 실제 관통 오류에는 접기 번호와 한국어 설명을 추가했다. 예: ‘7번째 접기에서 아래쪽 종이가 고정된 위쪽 종이를 관통합니다.’ 다른 UI 변경은 없다.

프리셋 저장→로드 및 실제 공원 작업대 열기→보관→같은 기체 꺼내기에서 형상·이력·용지·부위·기준점의 값이 유지됐다. 기존 검증기의 JSON 실수→native 접기 횟수 정수 정규화는 동일하게 수행되므로, 보존 비교는 JSON 숫자 타입을 통일한 뒤 모든 값을 비교한다. 원본 파일은 수정하지 않았다.

보관 실패도 실제 작업대에서 검사했다. 편집기의 현재 형상에 오류를 넣고 보관을 시도하면 오류를 표시하고 편집 화면을 유지한다. 그 순간의 형상과 되돌리기 이력은 변하지 않는다. 이후 원본을 복원해 정상 보관되는 것까지 확인했다.
