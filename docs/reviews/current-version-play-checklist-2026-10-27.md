# 현 버전 플레이 체크리스트

작성일: 2026-10-27. 기준은 공원 이동 방향·발사 준비 캐릭터 숨김·착지 복귀 버튼이 적용된 로컬 버전이다. 검증 오탐 수정 완료 여부는 별도로 기록한다. 공개 웹 버전과 로컬 버전이 같은 상태라고 가정하지 않는다.

아래 체크박스는 **사용자 확인 전** 상태다. 자동 검사 통과 보고와 직접 플레이 결과를 구분한다. 우선 1~3번을 이어서 확인하고, 여유가 있을 때 4~6번을 점검한다.

## 테스트 정보와 기록법

- 시작 시각: ____________________
- 창 크기/화면 배율: ____________________
- 검증 로직 수정본 포함: 예 / 아니오 / 확인 전
- 사용 용지: ____________________

통과하면 체크한다. 실패는 항목 ID와 함께 맨 아래에 기록하고 체크하지 않는다. 선행 기능 때문에 진행할 수 없으면 **진행 불가**로 적는다. 예: `F04 진행 불가 — V01 보관 오류로 후속 확인 불가`.

**저장 검증 상태 갱신:** 기존 16:43 덤프의 6회차 경계 접촉 오탐은 개발 수정 완료 보고를 확인했다. 다만 새 `pap_2026-10-27T19-59-16_67921230.json`에서는 원본 층 탐색 실패를 7회차 관통으로 오인하는 별도 문제가 재현됐다. [새 원인 분석](paper-source-mapping-failure-2026-10-27.md)에 따라 추가 수정을 요청한다. 저장 오류를 만나면 같은 작업을 반복하지 말고 덤프를 남긴 뒤, 공원에 있는 기존 기체로 이동·투척·회수 점검을 계속한다. 임시 우회를 위해 현재 접기나 저장 데이터를 덮어쓰지 않는다. V01~V03은 새 사례까지 통과하는 수정본에서 다시 확인한다.

## 1. 공원 이동·읽기 — 우선 확인

- [ ] **S01** 게임을 새로 시작한 직후, 접기·저장·도면 로드를 거치지 않고 Tab → ‘내 색종이’ → ‘꺼내기 · 손에 들기’를 누른다. 색종이가 손에 표시되고 오류가 없어야 한다. 2026-10-28 [초기 빈 이력 타입 수정](initial-paper-take-fix-2026-10-28.md)과 일반·Mono·GPU 자동 검사 통과를 확인했으며, 체크박스는 사용자 플레이 확인용으로 남긴다.
- [ ] **M01** 카메라 방향을 유지한 채 W/A/S/D를 각각 누르면 진행 방향으로 몸이 돌아간다. A/D는 옆으로, S는 뒤로 걸으면서 몸이 정면에 고정되는 현상이 없어야 한다.
- [ ] **M02** 카메라를 약 90° 돌리고 같은 조작을 반복해도 화면 기준 앞·뒤·좌·우로 이동하며 몸 방향이 맞는다. W+A/W+D도 자연스럽고 대각 이동만 빨라지지 않는다.
- [ ] **M03** 멈춘 뒤 우클릭으로 카메라만 돌리면 몸은 마지막 이동 방향을 유지한다. 벽에 막히거나 벽을 따라 이동할 때 몸 방향이 떨리지 않는다.
- [ ] **M04** 기체를 손에 들고 방향을 바꿔도 손·기체가 몸과 함께 움직인다. 종이가 몸 반대편에 남거나 손이 크게 뻗는 현상이 없다.
- [ ] **M05** 공원 상태·대상 안내·하단 행동을 평소 거리에서 읽을 수 있다. 작업대/발견물 근처에서 다음 행동을 바로 찾을 수 있는지도 확인한다.

## 2. 준비·발사 — 우선 확인

보관함 Tab → 기체 선택 → ‘꺼내기 · 손에 들기’ → Space로 준비한다.

- [ ] **F01** 준비 화면에서 캐릭터 머리·몸·손이 기체를 가리지 않는다. 기체 전체 모양과 어느 쪽으로 날릴지 알아볼 수 있다.
- [ ] **F02** 준비에서 우클릭으로 조준하고 휠로 거리를 바꿔도 기체가 UI에 묻히거나 화면 밖으로 크게 잘리지 않는다. 좌우 발사 방향을 따로 정하는 UI는 없다.
- [ ] **F03** 준비를 B로 취소하면 공원 화면과 캐릭터가 돌아오고 같은 기체가 손에 남는다. 다시 준비할 수 있다.
- [ ] **F04** Space/Enter 또는 주 버튼으로 게이지 시작 → 힘 확정 → 돌아오는 원점에서 마지막 입력까지 진행된다. 키를 길게 누른 한 번의 입력으로 여러 단계가 넘어가지 않는다.
- [ ] **F05** 게이지 도중 Esc를 누르면 발사 없이 게이지만 취소된다. 기체가 사라지거나 중복되지 않고 다시 시작할 수 있다.
- [ ] **F06** 발사하면 카메라가 기체를 따라가며, 기체가 화면에서 갑자기 사라지거나 캐릭터에 가려지지 않는다. 비행 중 B로 관람을 끝내도 기체는 월드에서 계속 비행한다.

## 3. 착지·회수·반복 — 우선 확인

- [ ] **L01** 착지 직후 거리·시간과 회수 안내가 보인다. 하단에 활성화된 ‘공원으로 돌아가기 [B / Esc]’가 있어 다음 행동을 추측할 필요가 없다.
- [ ] **L02** 복귀 버튼을 클릭하면 공원으로 돌아온다. 캐릭터가 보이고 이동할 수 있으며, 기체는 착지 위치에 남아 자동 회수되지 않는다.
- [ ] **L03** 다른 투척에서 B로도 복귀할 수 있다. 결과창을 연 상태에서는 Esc 첫 입력이 창을 닫고, 다음 입력이 공원으로 복귀한다. 키를 누르고 있다고 두 동작이 연속 실행되지 않는다.
- [ ] **L04** 착지 표식으로 이동해 E로 회수한다. 자신의 기체는 긴 발견물 관찰 절차 없이 회수되고, 보관함에 같은 기체가 하나만 들어온다.
- [ ] **L05** 회수 → 꺼내기 → 준비 → 투척을 3회 반복해도 보관 수량이 늘거나 기체가 사라지지 않는다. 직전 입력 때문에 복귀 직후 재발사되지 않는다.

## 4. 접기·부위·보관

현재 저장 오탐 때문에 보관이 막히면 C01~C04까지 확인하고 C05~C06은 진행 불가로 남겨도 된다.

- [ ] **C01** 작업대에서 E로 접기에 들어가 기본 색종이 15×15cm가 표시된다. 용지 선택에서 A4 21×29.7cm, 신문지 39.1×54.5cm, 도화지 39.4×54.5cm가 구분된다. 새 종이 선택은 현재 작업 보존 여부를 확인한 뒤 진행한다.
- [ ] **C02** 일반 드래그 접기와 ‘2’ 선 긋기가 가능하다. 선 긋기는 기존 기준점/선이 우선하고, 그 외 15° 방향 맞춤과 Shift 자유 각도 전환이 납득되게 작동한다.
- [ ] **C03** 한 겹/전체 겹 전환, F 뒤집기, Z 되돌리기 후 종이가 떨어져 나가거나 접기 횟수와 화면이 어긋나지 않는다.
- [ ] **C04** 날개 두 개와 손잡이를 표시·확정하고 펼친 모습을 확인한다. 의도한 축으로 양 날개가 열리고 손잡이가 아래에 놓인다. 의도적으로 비대칭으로 접은 종이의 비대칭 자체는 오류로 기록하지 않는다.
- [ ] **C05** ‘접기 마치고 보관 [B]’ 후 실물이 보관함에 하나 생긴다. 꺼내기/살펴보기/작업대 수정에서도 모양·용지·부위 지정이 유지된다. **V01 수정본에서 재확인이 필요하다.**
- [ ] **C06** ‘내 도면 [P]’에 새 이름으로 저장하고 불러오면 모양·용지·접기 이력이 유지된다. 도면 저장만으로 월드 실물이나 보관 수량이 추가되지 않는다. **V01 수정본에서 재확인이 필요하다.**

## 5. 발견물 관찰·처리

한 번 정리한 물건은 같은 세션에서 되돌릴 수 없으므로 **다시 놓기 → 재관찰 → 도면 저장 → 보관 확인**을 먼저 하고, 정리하기는 마지막 또는 별도 실행에서 확인한다.

- [ ] **I01** 처음 보는 발견물 근처에서 E를 누르면 3D 살펴보기로 들어간다. 왼쪽 드래그로 회전, 휠로 확대, ‘시점 초기화’가 동작한다. 관찰 중 공원 캐릭터가 함께 움직이지 않는다.
- [ ] **I02** 날개 축이 있는 발견물은 ‘접힌 모습 / 펼친 모습’으로 비교할 수 있다. 날개 축을 찾지 못한 물건은 이유를 안내하고 임의의 축으로 펼치지 않는다.
- [ ] **I03** ‘다시 놓기 [Esc]’는 물건을 월드에 남기며, 다시 살펴볼 수 있다. ‘보관하기’는 월드에서 제거하고 보관함에 하나만 넣는다.
- [ ] **I04** ‘내 도면으로 남기기’는 실물 처리와 별개로 동작한다. 도면 저장 후 실물을 보관하거나 정리할 수 있다. 저장이 V01 오류로 막히면 실패 문구와 덤프를 기록한다.
- [ ] **I05** ‘정리하기 · 발견물 기록’은 물건을 제거하고 처리 기록을 남긴다. 현 버전은 보수를 주지 않는다는 안내와 실제 처리가 일치한다.

## 6. 작은 창·시야·입력 마무리

- [ ] **U01** 1280×720과 작은 창(가능하면 640×360)에서 공원·준비·착지·살펴보기를 확인한다. 주요 문구·주 버튼이 잘리지 않고 클릭할 수 있다.
- [ ] **U02** 밝은 바닥·어두운 배경에서도 글자를 읽을 수 있다. 바람 UI가 우측 하단에 있고 결과창은 필요할 때 열고 닫을 수 있다.
- [ ] **U03** 보관함·도면·관찰·결과창을 닫은 입력이 뒤의 공원 이동/발사로 이어지지 않는다. 창 밖으로 포커스를 옮겼다가 돌아와도 드래그나 이동이 붙잡혀 있지 않는다.

## 검증 오탐 수정본 도착 후

- [ ] **V01** 같은 A4 접기 흐름으로 보관·도면 저장을 다시 시도해 정상 완료되는지 확인한다. 이전 덤프의 정확한 이력 재검증은 개발 세션의 자동 재현 결과로 대조한다.
- [ ] **V02** 저장한 종이를 다시 꺼냈을 때 실패를 없애려고 모양이나 접기 이력이 바뀌지 않았는지 확인한다.
- [ ] **V03** 개발 완료 보고에서 원본 덤프 통과와 기존 실제 종이 관통 사례 거부가 모두 유지됐는지 확인한다. 사용자가 일부러 종이를 뚫는 접기를 재현할 필요는 없다.

## HUD·오디오 개선본 — 2026-10-28 추가

[개편·음원 적용 기준](hud-audio-plan-2026-10-28.md)에 따른 [구현·자동 검증 완료](hud-audio-implementation-2026-10-28.md)를 확인했다. 아래 항목은 해당 개선본에서 확인한다. 자동 검사와 사용자 청감은 구분하며, 체크박스는 직접 확인 전 상태다.

- [ ] **H01** 결과창을 열면 상단 메뉴·수치보다 앞에 표시되고 제목·닫기가 가려지지 않는다. 뒤쪽 버튼/기체를 클릭해도 다른 행동이 실행되지 않고, Esc 첫 입력은 결과창만 닫는다. 작은 창에서도 반복한다.
- [ ] **H02** 투척 고도각을 큰 숫자로 바로 읽고 ±/↑↓/안내된 조작으로 바꿀 수 있다. 준비 중 화면 숫자가 실제 조준과 함께 바뀌고, 힘 게이지 시작 후에는 목표각이 잠긴다.
- [ ] **A01** BGM이 나오고 공원→접기→보관함→투척→공원 왕복에서 처음부터 반복 시작하거나 두 곡이 겹치지 않는다.
- [ ] **A02** 접기를 확정하면 종이 소리가 나고, 미리보기 드래그·접기 취소만으로 확정음이 반복되지 않는다. 뒤집기/펼침도 짧은 피드백이 있다.
- [ ] **A03** 힘을 정할 때와 실제 던질 때 소리가 구별된다. 발사 취소·벽에 막힌 발사에서는 투척 성공음이 나지 않는다.
- [ ] **A04** 착지음이 한 번 들리며 튀거나 굴러도 계속 반복되지 않는다. 관람만 종료했을 때 착지음이 나지 않는다.
- [ ] **A05** 손에 꺼내기·실제 수거/회수·정리·저장 성공에 소리가 나고, 단순 살펴보기와 취소를 획득 성공처럼 들려주지 않는다.
- [ ] **A06** 걸으면 작은 발걸음이 들리고, 정지·벽에 막힘·창 조작 중에는 멈춘다. 종이 소리보다 과하게 크지 않다.
- [ ] **A07** 음악/효과음 음량과 음소거가 따로 동작한다. 장면 왕복 후 설정이 유지되고, 접기/투척음을 BGM이 가리지 않는다. 반복하거나 갑자기 큰 소리가 있으면 이벤트명과 함께 기록한다.

## 발견한 문제 기록

아래 양식을 문제마다 복사한다. 인터럽트가 발생하면 오류가 없어도 ‘어디서 다음 행동을 찾았는지’를 남긴다.

```text
항목 ID / 결과(실패·진행 불가·불편):
실행 경로·시각 / 수정본 포함 여부:
화면·용지 / 직전에 한 조작:
기대했던 동작:
실제 동작 / 반복 재현 여부:
덤프 파일 또는 스크린샷 경로:
다음 행동을 찾는 데 걸린 시간·헤맨 지점:
```

버그 발생 시 가능하면 **그 상태에서 Ctrl+Shift+D로 덤프를 먼저 남긴다**. UI와 글자 가림 문제는 스크린샷도 함께 남긴다. 공원 실물·발견물 상태는 현재 세션 범위라 재실행하면 동일 상태가 보존되지 않을 수 있다. 영구 보관 목적이면 ‘내 도면’ 저장을 구분해서 사용하되, 현재 V01 오류가 저장을 막을 수 있다는 점에 유의한다.

랜덤 발견물 생성·봉사 보상 경제·정식 공원 미술·정식 투척 모션·기기별 물리 정확도는 이번 체크리스트의 완료 조건에서 제외한다. 현재 구현된 반복 플레이의 조작과 안내를 우선 평가한다.
